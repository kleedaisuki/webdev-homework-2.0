# 演示脚本：星河工坊 · 2026 世界杯专题站

面向助教评审的 12 分钟现场演示路线。八幕，每幕给出「点哪里 → 屏幕上会出现什么 → 说什么」，末幕把演示数据清回原状，方便下一组或第二天重跑。

- 适用版本：`main` 分支（W17 双旅程与 W09 首页验收已合并）
- 站点地址：`http://127.0.0.1:8080`
- 演示账号：`preview` / `Preview2026!`（若已改密码，用 `php yii account/create-admin` 新建）
- 演示数据：全部是课堂演示数据，带「演示数据」角标；四场官方样本始终标「FIFA 官方来源」并附核对日期

## 0 演示前 5 分钟

1. 启动 MySQL：`D:\mysql-8.0.46-winx64\bin\mysqld.exe --console --datadir=D:\mysql-8.0.46-winx64\data`
2. 启动站点（仓库根目录）：`php yii serve 127.0.0.1 --port=8080`
3. 打开 `http://127.0.0.1:8080/`，确认首页有精选赛果卡片，说明数据库连接正常。
4. 准备两个标签页：`/world-cup/matches`（前台）与 `/admin/login`（后台）。演示时来回切换，观众能看到「改了后台，前台就变了」。
5. 想确认数据是干净的，先跑一次 `php tests/w21-demo.php`（它会自动重置演示数据并走完整条流程，见附录 C）。

> 演示期间不要重跑迁移，也不要执行 `php yii seed/fixtures` 之外的导入。若上一次演示中断留下半条记录，直接按第 8 幕的重置步骤清理。

## 第 1 幕 · 官方赛果是有出处的（约 2 分钟）

| 操作 | 屏幕上的结果 |
| --- | --- |
| 打开 `/world-cup/matches?status=finished` | 列表显示已完赛场次，每张卡片有开球时间、场馆、两队与比分 |
| 点第一张卡片的「详情」 | 详情页显示届次、阶段、小组、比分、开球时间、场馆 |
| 指「数据来源」一行 | 显示 FIFA 官方来源链接与核对日期 |

**口播**：赛果不是编的。四场官方样本录自 FIFA 公布的 2026 赛程，落库时把来源链接和核对日期一起存下来，页面上直接给出出处。开球时间按北京时间显示，数据库里统一存 UTC，换算在展示层做。

**检查点**：详情页能看到 `2 : 0`、`FIFA 官方来源` 和核对日期，且没有「演示数据」角标。

---

## 第 2 幕 · 后台新建一场演示比赛（约 2 分钟）

| 操作 | 屏幕上的结果 |
| --- | --- |
| `/admin/login`，输入 `preview` / `Preview2026!` | 进入工作台，显示「你好，预览账号。」 |
| 工作台点「赛事管理」 | 赛事列表，官方场次操作列写「只读」 |
| 点「新建演示比赛」 | 表单：本届赛事 / 小组 / 主队 / 客队 / 场馆 / 开球时间 / 比赛状态 / 比分 |
| 选 `2026 FIFA World Cup`、`F` 组、主队 `Argentina`、客队 `Belgium`、场馆 `Dallas Stadium`、开球 `2026-06-11 20:00:00`，状态「未开赛」，比分留空 | — |
| 点「保存」 | 回到列表，出现一条「草稿」记录，提示「演示比赛已保存为草稿。」 |
| 切到前台 `/world-cup/matches` 刷新 | 列表里**没有**这场比赛 |

**口播**：新建的记录默认是草稿。草稿不进公开查询，所以前台看不到；就算有人猜到详情地址，服务端也会返回 404。开球时间输入的是北京时间，保存时转成 UTC。

**检查点**：后台列表有这场草稿，前台列表没有；直接访问 `/world-cup/matches/{id}` 是 404。

---

## 第 3 幕 · 发布成「未开赛」（约 1 分半）

| 操作 | 屏幕上的结果 |
| --- | --- |
| 回后台列表，点这场比赛的「编辑」 | 编辑页带发布按钮 |
| 点「发布到前台」 | 提示「已发布到前台。」，列表发布状态变为「已发布」 |
| 前台 `/world-cup/matches?status=scheduled` | 列表出现这场比赛 |
| 点进详情 | 角标「演示数据」，比分位置显示「未开赛」，没有比分 |

**口播**：发布是一次独立操作，发布会写入发布时间；重复点不会改原来的发布时间。这场还没踢，所以比分是空的——空和 0:0 是两个不同的状态。

**检查点**：未开赛筛选里有这场；详情显示「未开赛」，页面不出现 `0 : 0`。

---

## 第 4 幕 · 录入 0:0（约 2 分钟）

| 操作 | 屏幕上的结果 |
| --- | --- |
| 后台编辑这场比赛 | 比赛状态选「已完赛」，主队比分 `0`、客队比分 `0` |
| 点「保存」 | 提示「修改已保存。」 |
| 前台 `/world-cup/matches?status=finished` | 列表第一张就是这场，比分 `0 : 0` |
| 点进详情 | 比分区显示 `0 : 0`，角标仍是「演示数据」 |

**口播**：0:0 是合法比分，和「未开赛」完全不同：未开赛不显示比分，0:0 显示两个零。后台只接受两个非负整数，缺一个就拒绝保存；录完分会刷新这条记录的比分更新时间，赛果排序按这个时间走。

**检查点**：已完赛列表出现 `0 : 0`；官方四场样本的比分与来源没有变化。

---

## 第 5 幕 · 改团队简介（约 1 分半）

| 操作 | 屏幕上的结果 |
| --- | --- |
| 前台 `/team` | 团队页显示当前简介 |
| 后台工作台点「团队资料管理」 | 表单：团队名称 / 团队简介 / 团队资源链接 |
| 简介末尾加一句「（演示改写）」 | — |
| 点「保存团队资料」 | 提示保存成功 |
| 回到 `/team` 刷新 | 简介变了，成员卡片与资源链接都还在 |

**口播**：团队栏目是同一套后台在维护，和赛程管理共用登录态，但互不影响。成员资料在成员列表里单独编辑，这里只改团队级信息。

**检查点**：前台团队页出现改后的文字，四位成员卡片仍在。

---

## 第 6 幕 · 留言一过一拒（约 2 分钟）

| 操作 | 屏幕上的结果 |
| --- | --- |
| 前台 `/guestbook`，用两个昵称各提交一条留言 | 提交后回到列表 |
| 看列表 | 两条都**没有**出现 |
| 后台 `/admin/messages` | 「待审核」里有这两条，带审核备注输入框 |
| 第一条点「通过」，备注写「演示：内容合规」 | 该条离开待审核 |
| 第二条点「拒绝」，备注写「演示：内容不合规」 | 该条进入已拒绝 |
| 回前台 `/guestbook` 刷新 | 只有通过的那条出现 |

**口播**：留言先入库、后审核。待审核和已拒绝都不进公开列表；审核动作与备注会留在后台记录里，方便追溯。公开页不做富文本渲染，用户输入按纯文本输出。

**检查点**：公开列表只有通过的留言；被拒绝的那条在后台「已拒绝」里能看到。

## 第 7 幕 · 作业下载（约 1 分钟）

| 操作 | 屏幕上的结果 |
| --- | --- |
| 打开 `/downloads` | 「团队作业」区列出本站交付的 PDF |
| 点其中一份 PDF | 浏览器打开或下载该文件 |

**口播**：交付物直接从仓库的 `data/team/` 目录读出来，站点只允许下载白名单扩展名，目录本身不能通过 HTTP 浏览。

**检查点**：PDF 能打开，文件名与 `data/team/` 里的文件一致。

## 第 8 幕 · 重置演示数据（约 1 分钟）

演示产生的三类痕迹要一起清掉：演示比赛、演示留言、被改过的团队简介。

```sql
-- 1) 审核记录先删（guest_review 以 RESTRICT 引用 guest_message，顺序反了会报外键错误）
delete from guest_review
 where message_id in (select id from guest_message where nickname like '演示访客%');

-- 2) 演示留言
delete from guest_message where nickname like '演示访客%';

-- 3) 演示比赛（保留种子里的 demo-classroom）
delete from fixture where sample_key regexp '^demo-[0-9]{8}-';

-- 4) 团队简介还原为原句
update project_team
   set summary = '四个人，一座看台。我们把数据、设计与代码连接起来，为 2026 世界杯留下属于自己的项目记录。'
 where id = 1;
```

重置后核对三件事：前台 `/world-cup/matches` 不再出现刚才那场；`/guestbook` 里没有演示留言；`/team` 的简介回到原句。

完整的 20 条固定入口（含页面标题与返回路径）见 `docs/w17-validation.md` 的「固定入口清单」。

## 附录 B · 现场故障排查

| 现象 | 处理 |
| --- | --- |
| 打开站点 502 / 连接被拒绝 | 站点没起：`php yii serve 127.0.0.1 --port=8080` |
| 页面报数据库错误 | MySQL 没起，按第 0 节第一条启动 |
| 登录提示「用户名或密码错误。」 | 账号不存在或密码改过，重建：`php yii account/create-admin` |
| 演示比赛在列表里重复出现 | 上一次中断没重置，按第 8 幕清理后重来 |
| 详情页 404 | 大概率访问的是草稿或非 2026 届的场次，属预期行为 |

## 附录 C · 自动走查

八幕可以一次性跑完：站点启动后执行

```
php tests/w21-demo.php
```

脚本会用真实表单走完「草稿 → 发布 → 录 0:0 → 改简介 → 留言一过一拒 → 下载 → 重置」，逐条打印 PASS/FAIL，结束时把演示数据清回原状。它既用于验收前自检，也方便下一位演示者确认环境正常。
